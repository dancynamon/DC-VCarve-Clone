# Aquamentor CAD/CAM — engine & architecture

## ★ NEW: full CAD editor — `../cadcam-studio-260614.html`
Editor-first, VCarve-style. Draw + edit vectors, then cut. Single self-contained file.
- **Draw:** select, node-edit, line, polyline, **bezier curve (pen tool)**, rectangle, circle, ellipse, arc, polygon, star, single-stroke text, measure.
- **Fillet / Trim / Extend** (Edit tool group): **Fillet** rounds a clicked corner with a tangent arc (Fillet r radius, auto-clamped to the shorter edge); **Trim** cuts the clicked part of an open vector back to where it crosses another vector; **Extend** stretches an open vector's endpoint along its direction to the next vector ahead. Core: `filletPolyCorner` / `trimPolyline` / `extendPolyline` / `segInt` / `pathIntersections`.
- **Curve (bezier) tool:** click anchors, drag to pull symmetric handles; Enter finishes, click the start node to close. Stored as `prim:{kind:'bezier',nodes}`, flattened to `pts` so CAM/preview/export just work. Node-edit shows draggable anchors + handles (green = smooth, tan = corner; dbl-click toggles). Core: `mkBezier`/`flattenBezier`/`reflowBezier`/`mirrorSmoothHandle`.
- **Edit:** move / **scale (8 handles — a single unrotated rect/round/circle/ellipse stays parametric: dims update in the prim, and non-uniform-scaling a circle becomes an ellipse)** / **rotate about center from any of 4 corner grips (Shift = 15° snap; a single rect/round/circle/ellipse/polygon/star stays parametric — the grip accumulates its prim rotation so it remains editable in the dialog)**, offset, **weld (union) / subtract / intersect** (Clipper booleans), join, mirror H/V, rotate 90°, duplicate, array (rows×cols), align (6-way), node add/delete/drag.
- **Dimension annotations (B3):** the **Dim** tool (shortcut **D**) draws VCarve-style dimensions — **aligned**, **horizontal**, **vertical**, **radius**, **diameter** and **angle** (3-point). Each one is a `type:'dim'` shape carrying only its defining points in `prim` (`a`, `b`, optional `c`, plus `style/off/textH/prec/unit/label`); every extension line, dimension line, solid arrowhead and single-stroke label is regenerated on demand by `cadcore.dimensionGeometry(prim)`, so moving an endpoint or switching style redraws the whole annotation. Labels auto-format in **in / mm / plain** at a chosen precision (`fmtDimValue`) with an optional manual override (e.g. `TYP 4X`), and prefix `R` / `Ø` / `°` automatically. Placement: click the two measured points then click to place the line (the offset is picked up live from the cursor); radius/Ø = centre then edge; angle = vertex, ray, ray, radius. Tight spans flip their arrows outboard automatically. Dimensions are **annotations** (`annotation:true`) — `shapesToContoursInput` drops them so they never reach CAM, and "Check vectors" ignores them — but they still export to DXF/SVG and round-trip through `.aqcam`. Double-click one for the numeric dialog (style/units/decimals/offset/label). Core: `mkDimension`/`dimensionGeometry`/`dimValue`/`fmtDimValue`/`measureText`.
- **Snapping:** grid snap + object snap (endpoints, midpoints, centers) + **job/material corners, edge midpoints & center** (corner = diamond marker); ortho with Shift.
- **Selection:** click an edge **or click inside** a closed contour to pick it (VCarve-style); marquee box-select; shift to add.
- **Right-click menu:** right-click a shape for Edit dimensions…, Duplicate, Delete, Mirror H/V, Rotate 90°, Offset…, Array…, Bring to front / Send to back (and Weld/Subtract/Intersect when 2+ are selected).
- **Numeric edit (VCarve-style dialog):** double-click a shape (or right-click → Edit dimensions…, or Properties → **Edit…**) for a modal with exact fields per type — rect/round (X/Y/W/H + corner radius + rotation°; a radius >0 promotes a rect to rounded), circle (center/radius + rotation°), ellipse/polygon/star (center, radii, sides/points, rotation°), line (endpoints + rotation°), arc (center/radius/angles), text (string/pos/height). Rotation° on rect/round/circle/ellipse/polygon/star is stored and round-trips (re-opens showing the angle); on line and generic vectors it's applied as a delta about the center. Non-parametric vectors get a generic X/Y/W/H (move+scale). **Live preview** — the shape updates on the canvas as you type; the dialog is draggable (so it never hides the shape) and the backdrop is lightly dimmed. Apply commits as a single undo step; Cancel/Esc reverts.
- **Job/material:** set W×H×thickness + origin; drawn as a clear bordered/shadowed stock panel with corner brackets, a size caption (`W" × H" · T" thick`), and edge dimension labels; updates live as you type.
- **Aspire-matched two-dock layout** (rebuilt from screenshots of the real install, kept in `docs/vcarve-reference/`): a **menu bar** (File / Edit / Toolpaths / View / Help) with working drop-downs; a **left "Drawing" dock** — File Operations, 2D View Control, Create Vectors, Transform Objects, Edit Objects, Align Objects, Offset and Layout — with a **Job Dimensions** readout at its foot and **Drawing / Clipart / Layers** tabs along the bottom edge; and a **right "Toolpaths" dock** — Material Setup (Set…, Z0/thickness, XY datum), a Toolpath Operations icon grid, and a **Toolpath List** that stays visible under whatever form is open. **Form-in-panel is per dock**: a drawing tool takes over the left dock body, a toolpath operation takes over the right dock's upper area, and the two never clobber each other. Shape forms accept exact numeric input (Width, Height, Diameter, Sides, Inner %, centre X/Y) plus a **Create** button, so geometry can be made without touching the canvas; dragging still works. Toolpath forms group fields the way VCarve does (Cutting Depths / Tool / Machine Vectors / Inlay fit / Lead in-out / Bridges-tabs / Output) and show only the fields the chosen operation uses. All tool and toolpath buttons carry a **hand-drawn 24×24 inline-SVG icon** (`ICONS` / `paintIcons()` in `studio_app.js`) on a single 1.6px stroke weight, using `currentColor` so the hover/active states still apply; the glyphs depict the operation (profile = an offset path around a shape, pocket = concentric clearing rings, v-carve = a V groove in section, inlay = a plug and its socket) rather than standing in with letterforms. The **canvas theme** is token-driven (`THEMES` / `TH()` in `studio_app.js`): the 2D view draws dark ink on a near-white ground, and the 3D view uses the lavender gradient `#babbf4 → #e0e0f8` measured from the reference screenshots; every stroke, fill, handle, label and depth ramp reads from that table, so the whole look retunes in one place. The UI layer alone changed — `cadcore.js`, `camcore.js`, `bitmaptrace.js` and `clipart.js` are untouched.
- **True 3D view (`glview.js`)** — the Preview heightfield is triangulated into an actual solid (top surface + perimeter walls dropping to the stock floor + a base) and drawn in **WebGL** with a single directional light, so pocket walls and V-groove flanks read as geometry rather than shading. **Drag to orbit, shift-/right-drag to pan, wheel to zoom, double-click to reframe.** The interesting parts are pure and unit-tested without a GPU — `buildHeightMesh(field,{step})` (with decimation so a fine sim stays under ~1.2M verts) plus `perspective`/`lookAt`/`orbitEye`/`clampPitch`; only the buffer/shader plumbing in `createRenderer(canvas)` touches WebGL, and it returns `null` on failure so the view falls back to the flat top-down shading. The **toolpath moves are drawn over the solid** as GL lines (`buildToolpathLines`, also pure): cut moves in amber, rapids in grey and off by default, each lifted a hair off the machined surface because they sit exactly on it and would otherwise z-fight — both toggleable in the 3D footer. Panning moves the orbit target along the true screen axes (`s = f × up`), so the model follows the cursor and you are never locked to the job centroid. `gltest.js` guards it with 44 checks. No external 3D library — the studio stays one offline file.
- **Layers, undo/redo (Ctrl+Z/Y), pan/zoom, fit (F)**, hotkeys (V/N/L/P/R/C/E/A/G/T/M).
- **2D Design / Preview tabs** — a VCarve-style tab strip over the canvas. "2D Design" is the vector editor; "Preview" shows the machining result, read-only (grid + editing handles hidden). The active tab persists in the `.aqcam` project (`meta.view`).
- **3D material-removal simulation** — in Preview, a "3D cut" toggle renders a z-buffer heightfield sim: flat stock (job W×H×thickness) is carved by sweeping each toolpath's tool profile (flat / ball / V-bit by op) along its moves, lowering cells to `min(current, tool-surface)`; deeper passes win, overcuts clamp to the stock floor. Shaded top-down as a wood-tone depth map with directional hillshade for a carved 3D look. Resolution selectable (0.08–0.02"). Pure core: `camcore.simulateStock({x0,y0,w,h,thickness,res,cuts})` → heightfield + `stockHeightAt`. This is the substrate for the future Aspire 3D relief work.
- **Project save/load** — "Save job…" writes a versioned `.aqcam` JSON project (shapes + prims/text, layers, job/material, and the queued toolpath ops); "Open / Import" and drag-drop reopen it. Autosaves to localStorage (debounced on change + every 30s) and offers "Restore last session?" on load. Own format, not Vectric `.crv`. Core: `projectToJSON`/`projectFromJSON` (versioned, validates + rejects unknown versions).
- **Bitmap import + trace (D1):** drop a **PNG / JPG / GIF / BMP / WEBP** in (or Open / Import) and the studio loads it as a reference image under the vectors, then opens a **Trace Bitmap** dialog — Threshold, Invert, Despeckle (px), Smoothing tolerance (px), Corner rounding and output Width" — with a **live vector preview** over the bitmap and running stats (contours, outer vs hole, point count before/after, traced size, specks dropped). **Trace** commits the contours onto a dedicated `trace` layer, selected and ready to pocket / profile / V-carve. Only the *decode* is DOM-bound (a canvas gives us RGBA pixels); the whole pipeline below it is `bitmaptrace.js` — `thresholdBitmap` (luma + alpha cut, flipped to y-up) → `despeckle` (4-connected labelling: drops ink specks AND fills enclosed pinholes, never background that reaches the border) → `traceBitmap` (walks every ink/background pixel edge with **ink on the left**, so outer contours come out CCW and counters CW — exactly the winding Clipper and the even-odd region builder want, so a traced logo pockets with its holes intact and no separate hole detection) → `simplifyPath` (Ramer–Douglas–Peucker, closed loops split at their farthest vertex first so no kink is left at the seam) → `smoothPath` (Chaikin corner-cutting that preserves any vertex turning more than `cornerAngle`) → scale to inches by **dpi or a target width**. Rasters are capped at 1400px on the long edge — past that the trace is slower without being more accurate. `tracetest.js` guards it with 45 checks. The reference bitmap is session-only (it is not written into the `.aqcam` project).
- **Import** DXF + SVG + **vector PDF** as **editable** geometry; **export** DXF / SVG. PDF import extracts path geometry from content streams (paths, Bézier curves, rectangles, q/Q/cm transforms) scaled to real inches — for cutting shapes out of logos/artwork. Resolves **Form XObjects** (the `Do` operator with per-form `/Matrix`, recursive + cycle-guarded) since Illustrator/Corel wrap art in them. Ships a pure DEFLATE/zlib inflater so FlateDecode streams decode offline with no dependency; works with both classic-xref and xref-stream PDFs. **Live text is detected and warned** (the importer flags `hasLiveText` so the UI tells you to outline the fonts and re-export) rather than silently dropped. Not supported (yet): raster/scanned PDFs, cutting live text directly, clip regions.
- **CAM built in (Op selector):**
  - **Profile** — outside/inside/on, climb/conv, multipass, holding tabs.
  - **Pocket** — concentric offset-stepover clearing (stepover %), respects islands/holes, multipass. **Large/small tool rest machining:** set a "Finish Ø" and the op emits TWO toolpaths — the primary (large) tool roughs the bulk, then a smaller finish tool rest-machines ONLY the sharp corners / narrow necks the big tool's radius rounded off (rest area = `inset(region,r_small) − inset(opening(region,r_big),r_small)` in tool-center space). Each op carries a `toolProfile` for the 3D sim; a fully-convex pocket leaves no rest work (stays single-op).
  - **Lead-in/out** (Profile + Pocket) — tangential **arc** or **line** entry/exit of a chosen length, on the non-gouging side (outside for outside-profile, inside for inside/pocket), kept at cut depth so the plunge lands off the finished edge; auto-skipped (with a warning) on contours too small to fit it. Optional **Z ramp-in** (Ramp" length) descends clearZ→cutZ over the first part of the lead-in instead of plunging straight (0 = straight plunge). A ramped **arc** lead emits a **helical G2/G3 + Z** move on posts that support it (`helical:true`, default for ShopSabre/Generic) — split into a descending sub-arc (clearZ→cutZ over exactly Ramp") + a flat sub-arc to the contour start when Ramp" is shorter than the lead-in arc, or one descending helix when Ramp" ≥ the arc length; line leads and helical-off posts fall back to G1 ramp segments.
  - **Drill** — one hole at each closed contour's centroid, optional peck depth; green hole markers on the backplot.
  - **V-Carve** — true medial-axis (grassfire/distance-transform skeleton) groove, depth = inscribed-radius ÷ tan(½·bit-angle), capped by Cut depth (0 = full sharp V); pairs with TTF outline text. **Flat-depth area clearance:** set a Flat" depth + a clearance endmill Ø and the op emits TWO toolpaths — a flat endmill pocket that roughs the deep interior (where the groove would exceed the flat depth) down to flat depth FIRST, then the V-bit finishing the tapered walls capped at flat depth (bevelled prism with a flat machined floor). Each op carries a `toolProfile` so the 3D sim renders the right tool.
  - **Inlay (C5)** — a *matched pair* of toolpaths from one design: the **female** cavity machined into the base board and the **male** plug machined from the contrasting board, flipped over and glued in. Two fits: **Straight** (female = pocket to Cavity", male = outside profile to Plug" — use tabs, the plug becomes a loose part) and **V-carve** (tapered walls that wedge together: female = V-carve with a flat floor at Cavity"; male = V-carve of the **field around** the design — a frame Field" outside its bounding box with the design as islands — which leaves the design raised on V-tapered walls). The fit **Gap"** (per side) is machined into exactly one half — the cavity by default, so the plug keeps the design's true size; switch **Gap on** to Plug to keep the cavity true instead. **Start"** sinks the male V-carve below the plug's face, which is what makes the plug seat on its taper instead of bottoming out on the cavity floor (a 0 start depth warns). The male toolpath is **mirrored in X** (the plug is flipped face-down), and each mirrored closed pass is reversed so climb/conventional survives the flip. **Part** cuts Both / Female / Male, and every emitted op is tagged `part:'female'|'male'` so the pair can be posted together or split. Core: `camcore.inlayOp(contours,opts)` → `{ops,warnings,parts:{female,male}}`.
  - All → **G2/G3 arcs** → ShopSabre/Generic post → live **depth-shaded backplot** (cut moves tinted shallow→deep by Z, with a depth legend; rapids dashed grey) → **Export .tap**.
  - **Machining time estimate:** each toolpath row shows its estimated cut time (feed for cutting moves, plunge for Z-down, rapid for G0 — `camcore.estimateTime`), with the job total in the Preview status. Useful for quoting.
  - **Check vectors:** the Edit panel's "Check vectors" flags and selects open contours, duplicate vectors, and self-intersecting closed shapes (`cadcore.validateShapes`) before you cut.
  - **Editable TOOLPATHS list (VCarve-style):** "+ Toolpath" captures the current op + selection as a named toolpath. Each row has a show/hide checkbox (toggles it in the backplot), click-to-rename, an ✎ Edit action that loads its params + selection back into the CAM panel (button flips to "✓ Update" to write changes back in place), ↑/↓ reorder, and delete. "Recalc all" recomputes the combined depth-shaded backplot for every visible toolpath. "Post job" concatenates all toolpaths into one program (HEADER tool block for the first, TOOLCHANGE blocks for the rest) → one `job.tap`, applying nearest-neighbor pass ordering (`orderPasses`) to cut rapid travel; auto-assigns tool numbers from the saved Tool library by diameter and refuses to post if one tool number is used with two diameters. Toolpaths (name + visible + params + selection) persist in the `.aqcam` project.
- **Toolpath templates (C6):** a **Template** row in the TOOLPATHS panel — a reusable machining *recipe* holding only toolpath settings and **no geometry**, so "V-carve the text, then profile it out with tabs" drops onto whatever vectors are selected in a new job. **Apply** appends the recipe's toolpaths bound to the current selection (empty selection = all visible vectors), **Save…** captures the current toolpath list back out as a template, **Del** removes one, and **⤓/⤒** export/import a versioned `.aqtpl` JSON file (also openable via Open / Import and drag-drop). Params are **whitelisted on the way in and out** (`sanitizeTemplateParams`), so a hand-edited or foreign file can never smuggle selection ids, functions or junk keys into the CAM panel, and partial entries are filled from defaults so a hand-written template still runs. Ships five starter recipes (sign V-carve + cut out, pocket + corner finish, through cut with tabs, V-inlay pair, peck drill) and persists the library to localStorage. Core: `templateFromQueue`/`applyTemplate`/`normalizeTemplate`/`templateToJSON`/`templateFromJSON`/`upsertTemplate`/`removeTemplate`/`defaultTemplates`.
- **Clipart / shape library (D2):** a **CLIPART** panel of thumbnail swatches — click one, then drag a box on the canvas to place it at that size (a single click drops it 2" wide, with a live preview of the art and its box while you drag). Placed art lands on a `clipart` layer as ordinary closed vectors, ready to pocket / profile / V-carve. Ships **18 built-in pieces** across *Basic* (heart, star, starburst, arrow, chevron, cross, diamond, hexagon, gear), *Plaques* (round-corner plaque, oval, banner ribbon, shield) and *Pool & safety* (life ring, water drop, waves, no/prohibited, pool ladder) — all generated **procedurally** in `clipart.js`, so the catalogue is a few hundred bytes of code rather than a blob of coordinates and can be regenerated at any smoothness. Multi-loop pieces keep **CAM winding** (outer CCW, holes CW), so a gear or life ring pockets with its bore left uncut. **+ Selection** turns the selected closed vectors into a new library shape (name + category), **Del** removes a custom one (built-ins are protected), and **⤓/⤒** export/import a versioned `.aqclip` file (also openable via Open / Import and drag-drop). Custom shapes persist to localStorage. Entries are stored **normalized to a unit box** with their aspect recorded, so placement is just a scale — `placeClipart` fits and centres inside the box (or stretches with `keepAspect:false`), and `clipartThumbnail` is the same call into a preview square. Core: `builtinClipart`/`placeClipart`/`clipartFromLoops`/`normalizeLoops`/`libraryToJSON`/`libraryFromJSON`/`upsertClipart`/`removeClipart`.
- **Tool library:** saved presets (dia/feed/plunge/RPM/op/angle) in a dropdown; Save/Del; persisted to localStorage.
- **Self-test** (top bar): builds a sample design (rect + circle + single-stroke "AQ") and runs every CAM op (Profile w/ arc lead+ramp, Pocket, Drill, V-Carve) through `camBuild`, reporting "N/5 ops OK" in the status bar — a one-click smoke test of the pure core.
- `pdftest.js` guards the vector-PDF importer (30 checks = pure inflate vs zlib, path/curve/rect ops, cm/q/Q transforms, FlateDecode end-to-end, Form XObject `Do`/`/Matrix`/nesting/cycle-guard, live-text `hasLiveText` flag (Tj/TJ), PDF→CAM). 
- Engine: `cadcore.js` (pure, 169 unit tests — incl. 37 dimension-annotation checks) + `camcore.js` (CAM, 195 tests = profile/pocket/drill/v-carve/inlay/templates/leads/ramp/helical/tooldb/arc/raster/ordering/medial-axis). The camcore suite also covers the material-removal sim (flat-cut depth, V cross-section, deeper-pass-wins, floor clamp, rapid no-op). `smoketest.js` runs the studio Self-test's 5-op sequence headless on both posts (10 checks). `importtest.js` guards DXF (6 checks), BLOCK/INSERT explosion (6 checks + 1 non-uniform-scale), SVG (6 checks), ELLIPSE-in-block (2 checks), and DXF+SVG round-trip export (4 checks) = 25 import checks. `npm test` runs all nine suites (562 checks). `cliptest.js` guards the clipart library with 47 checks.
- **Text:** single-stroke engraving font (built in) **or real TTF/OTF outline text** — toggle "Outline (TTF)" in Shape params, **Load font…** (or drag-drop a `.ttf/.otf`), and placement traces the actual glyph contours (with counters/holes) as closed, cuttable vectors → Profile/Pocket/V-carve. Outline height = the "H" field. Parser: opentype.js (MIT), embedded in `package/opentype.js`.

The older `gcode-cadcam-260614.html` remains as the import-a-file → CAM/backplot viewer.

## Files

- `camcore.js` — pure CAM engine (no DOM). Runs in Node (tests) **and** embedded in the HTML.

- `clipart.js` — pure procedural shape library (built-in art, normalization, placement, .aqclip). Embedded in the HTML too.
- `bitmaptrace.js` — pure bitmap tracer (threshold / despeckle / boundary trace / simplify / smooth). Embedded in the HTML too.
- `test.js` — Node test harness. Run `npm test` from the repo root for all seven suites.

## Architecture (single-file, modular inside)
The HTML embeds three scripts: **Clipper** → **camcore** → **app**.
- **Viewer engine** (reused, unchanged): DXF parser, geometry flattening (lines/arcs/circles/ellipses/splines/bulges), world↔screen transform, pan/zoom/fit, tool library, layers, and the **G-code backplot simulator**.
- **camcore (new):** `assembleContours` (chain loose segments into closed loops) → `offsetLoop` (Clipper) → `profileOp` (toolpaths) → `postProcess` (G-code). Pure functions, fully unit-tested.
- **Integration trick:** CAM emits **G-code text**, which is fed through the existing `loadGcodeText()` → the toolpath display + simulator come for free. CAM output is just another G-code "file."

## What works now (v260614)
- Load DXF → it shows as art with layers.
- **CAM · Profile** panel: tool #, diameter, side (outside/inside/on-line), direction (climb/conventional), cut depth, pass depth (multi-pass), feed, plunge, RPM, top-Z, **holding tabs** (count/length/height), post selector.
- Selection model = **visible layers** (toggle layers in the left panel to choose what to cut).
- **Generate G-code** → backplots over the art (combined mode). **Export .tap** → downloads.
- Posts: **ShopSabre/WinCNC** — now matched **byte-for-byte** to the real Vectric post `ShopSabre_DC_ATC_speed_arc_inch.pp` (header `G90→M5/M51→T#→Z2→S→M3→g4 x 4→M50→F`, ATC `T#` no M6, mid-file TOOLCHANGE omits Z2, footer `G0 Z2`/park `X0 Y115`/`M5`/`m51`, no M30/G20, CRLF) and **Generic ISO**.
- **Arc fitting is chord-aware.** `arcCovers` used to check only that the sampled points lay on the candidate circle. That is necessary but not sufficient: a long straight edge carrying no intermediate samples (the 44" side of a 46" rounded rect) could be "fitted" by a 250"-radius arc through its endpoints and a neighbouring corner point — every sampled point sat on that circle, so the test passed, and the posted G2/G3 **bowed the cut out by an inch on each side**. A fitted arc must now also have near-uniform chords (`ARC_CHORD_RATIO`, since a tessellated curve does and a swallowed straight run does not) and stay within `ARC_MAX_SAG` of the polyline it replaces. Failure falls back to G1 lines, which is always geometrically exact.
- **Arc tessellation is size-independent.** `arcPolyline` used a fixed angular step, so error grew with radius — a 12" circle carried 0.06" of faceting, enough to be a cutting-accuracy problem *and* to stop the fitter recognising it as an arc. `arcStepFor(r)` now derives the step from the radius to hold chord height at `ARC_CHORD_H` (0.004") at any size, so circles arc-fit from 2.5" to 24"+ radius.
- **Arc output (G2/G3):** toolpaths are arc-fitted before posting — circles/fillets/round corners emit true `I/J` arcs (CW=G2, CCW=G3), straight edges stay `G1`. Arcs split at ≤270° for controller-unambiguous moves. Toggle in the panel ("Arcs G2/G3"); off = polyline `G1` only.

## How to extend safely
Edit `camcore.js`, run `node test.js` (keep it green), then re-embed into the HTML
(the HTML's embedded copy must be regenerated — the build concatenates Clipper +
opentype + camcore + cadcore + dxfparse + the app). Ask Claude to "rebuild the
CAD/CAM HTML from cam-engine."
